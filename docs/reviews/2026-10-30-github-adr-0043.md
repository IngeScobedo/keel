# ADR-0043 implementado: desviaciones y pendientes

- **Fecha:** 2026-10-30
- **ADR:** [0043](../adr/0043-github-prs-promociones-y-actions-en-vivo.md),
  aceptado el mismo día.
- **Commits:** f4dae73, a362004, 4a5e940 y el de Entregas.

## Desviaciones

### El inicio de sesión no usa un pane de tmux

El ADR dice que «Iniciar sesión en GitHub» abre un pane de terminal de Keel con
`gh auth login --web`. La GUI todavía no tiene terminal propia. Medido en esta
máquina, `gh auth login --web` sin TTY imprime el código de un solo uso y la URL
en stderr, y espera sin pedir Enter hasta que el humano autoriza.

Keel lanza ese comando sin terminal y muestra el código con botones para
copiarlo y para abrir `github.com/login/device`. `gh` sigue conduciendo el flujo
y guardando el token en su almacén; Keel no lo ve. El código no entra al store
de eventos: la GUI lo consulta mientras el diálogo está abierto.

### La promoción no usa un worktree

El ADR dice que el merge `--no-ff` se hace en un worktree de Keel de la rama
destino. En zero-reports eso choca con los hooks de husky (commitlint), que
necesitan `node_modules`; un worktree nuevo no los tiene.

La promoción calcula el merge con `git merge-tree --write-tree`, crea el commit
con `git commit-tree` (los dos padres y el mensaje del proyecto) y empuja ese
sha sin force. Es lo que hace GitHub del lado del servidor:

- no hay checkout ni worktree;
- no corren hooks locales;
- un conflicto se detecta antes de empujar y se informa con sus archivos.

Requiere git 2.38 o más nuevo; esta máquina tiene 2.43.

## Pendiente

- **El agente no tiene tools de GitHub todavía.** Falta que pueda leer la PR y
  los runs y pedir un merge (`pr_merge_request`); hoy sólo el humano los ve y
  opera.
- **Los eventos `ci.run.*`** (ADR-0043 §5) no se emiten: las tarjetas consultan
  los runs mientras están a la vista. El historial de un deploy queda en GitHub,
  no en el store de Keel.
- **Presupuesto de llamadas:** falta dejar de seguir lo que nadie está viendo
  cuando quedan menos de 500 llamadas a la API.
- **Lo pendiente de una promoción:** si trae PRs, se listan ellas; un commit
  directo sin PR dentro de esa promoción no aparece en la lista.
- **Rama con convención:** que el push del plan de git use
  `feat/<contexto>-<resumen>` (§7) en lugar de `keel/…` está sin cambiar.
